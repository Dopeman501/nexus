# Installed D215 source consolidated on main

This fork's `main` contains the complete source lineage of the locally installed
Windows `3.1.8-beta.2-d215.19` service and `d215-recovery-1` dashboard revision.
The parent pins matching dashboard/service commits in the sibling personal forks.
The overlay and RGB retain the exact upstream revisions used by that installation.

Included installed features:

- D215 discovery, bounded serial ownership, brightness, orientation/frame controls,
  shared Widget/circular Panels/background composition, and screen restart.
- Both recovery actions on the D215 failed-connection page: restart Nexus Control
  and the same firmware-backed screen restart offered in Settings.
- Audio Trigger backgrounds and live draft editing; shared Lighting Audio Trigger
  look controls and media support.
- Universal Audio Trigger widget with global and individual background/lighting
  enable/intensity controls, per-lighting-device overrides, serialized client
  requests, profile epochs, atomic native changes and receiving bounds.
- Compact Lighting picks that release existing pins after a confirmed start and
  resume paused lighting, plus immersive saved custom styles and preset retention.
- Shared spatial controls for built-in and custom animations, including rotation
  and zoom, along with the preceding Monitoring text-colour and pinned-toolbar work.
- The associated deterministic, API and isolated browser regression tests.

## Consolidation boundary

The new personal forks initially copied a newer upstream `main` corresponding to
the v3.1.9 release line. Consolidation records both histories while retaining the
reviewed installed-release source tree. This is an intentional Git `ours` strategy
merge, not a platform upgrade or history rewrite. The official upstream remains
available through each checkout's `upstream` remote.

Use the fork's `main` and its pinned submodules for this installed feature set.
Historical `local/d215-beta.2` branches remain in the ancestry; no uncommitted
feature source is required to reproduce the checked source tree. Machine settings,
credentials, installed app data, private rollback backups and generated packages
remain outside the source repositories.

## Build and verification scope

Follow the component READMEs for dependencies and commands. The Windows service
uses .NET 10; the dashboard uses its pinned npm lockfile and the service-target
build (`npm run build:service`). Native packaging also needs the existing overlay,
RGB and Windows runtime prerequisites. A successful managed/dashboard build is
separate from NativeAOT package publication and installation.

Source review and verification cover the installed feature set. The original
web toolchain has pre-existing dependency audit findings, and 18 English widget
strings are missing from the other locales; the current translation provider
falls back to raw keys for those strings. These limitations are retained explicitly
rather than changing runtime behavior during repository consolidation.

Repository consolidation does not reinstall, restart or exercise the physical
device. Hardware recovery, real-audio behavior and user-visible acceptance retain
the limits of their owning installation records.

Consolidation checks passed 1,476 dashboard owner tests, 298 native owner tests,
29 isolated production-browser scenarios, changed-file lint, TypeScript and the
service-target dashboard build. The consolidation merge keeps each reviewed
component tree identical to its fully committed installed-feature checkpoint.
