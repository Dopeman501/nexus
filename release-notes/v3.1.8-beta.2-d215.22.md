## Included behavior

- GL Transitions (214) and Curtains (12) in Nexus, with 226 still-image gallery
  tiles, ordered multi-selection, accent highlighting and temporary device/simulator
  auditions. The main toggle/duration applies to Slideshow and Audio Trigger
  activation/return. Beat swaps have their own toggle/duration inside Audio Trigger
  backgrounds, using the same selected effect list.
- Decoded opaque image/video transitions, including tested H.264 MP4 and VP8 WebM,
  plus bounded solid/shader frame handover. Initial Oscilloscope activation uses
  main timing; only actual rhythm-to-rhythm changes use beat timing. Playback keeps
  one incoming video decoder and freezes outgoing mutable frames before retirement.
- Optional validated native preferences, backward-compatible legacy reading,
  independent persistence and preset/profile/import/reset/AOT serialization.
  Transient audition leases remain separate from saved backgrounds and audio
  detector identity.
- An isolated [five-library comparison lab](https://github.com/Dopeman501/nexus-web/blob/73753f1f38c37b6380f66107328792c1affc0dba/transition-lab/README.md)
  with 290 effects, including pinned original Codrops demos and authored Motion/
  Anime presets. Only GL/Curtains enter the production bundle. Separate notices
  identify MIT/BSD content and the original GSAP standard no-charge terms; GSAP
  is not relabelled MIT or integrated into Nexus production.

## Build and test boundary

Use the component READMEs and pinned npm lockfile. The production dashboard uses
`npm run build:service`; the sampler has its own Vite/Vitest/Playwright entry and
loopback-only launcher. Transition browser fixtures build from committed source
into ignored caches; video generation needs the documented local ffmpeg/ffprobe
prerequisites. No test downloads dependencies, opens the physical device or writes
installed Nexus settings.

Native Windows builds use .NET 10 and the existing overlay/RGB/runtime prerequisites.
The installed `.22` publication supplied `_NexusDevVersion=3.1.8-beta.2-d215.22`
as an MSBuild property; an ordinary development build retains the project's
development version. Repository publication does not publish a new binary release,
replace user settings or reinstall Nexus.

The installed acceptance record verifies 905 payload files (842 web/63 native),
71 served entry assets and both selected engine chunks. Seven saved configuration
files and exact custom-animation bytes are preserved; the existing D215 stream is
1680×756 at 30 fps with confirmed 80% brightness. Eleven isolated browser scenarios
pass against the installed files, with all application HTTP/WebSocket traffic mocked.
Source checks also include 39 existing picker/video/compatibility browser cases,
364 related native cases and 14 compiled hardware-disabled AOT checks. These are
software/installation results; physical appearance, timing and throughput remain
user-operated acceptance.

Fresh main-publication checks pass 686 dashboard owner tests, 307 sampler tests,
12 video-fixture contract cases, types/lint and both dashboard/sampler builds.
The portable browser setup passes all 226 production effects and portrait resize,
six decoded-video core cases and 11 Audio Trigger/UI cases. Six video-core cases
and one portrait case also pass with dashboard asset variables unset, verifying
that source harnesses do not depend on a prebuilt application. All 39 pinned
Codrops vendor blobs retain exact upstream bytes; two files retain original
upstream whitespace rather than rewriting the pinned source.

The dashboard toolchain retains its previously documented npm audit debt. The
fresh publication audit reports 29 affected package entries, including one critical
and 12 high, identical to the pre-transition baselines. The seven added transition
package nodes have no reported findings; all existing lock entries are unchanged.
The critical [proxy-addr advisory](https://github.com/jshttp/proxy-addr/security/advisories/GHSA-jqcg-44mw-7w3h)
requires trust-subnet configuration absent here. None of the critical/high packages
appears in the installed ASP.NET/static dashboard runtime, but the inherited
[compression advisory](https://github.com/expressjs/compression/security/advisories/GHSA-vc2v-76pw-4v95)
does affect standalone Node hosting through `npm start`. That risk remains
unresolved; this merge does not deploy that server or upgrade dependencies.

rollback backups, generated packages and local verification reports are not source
