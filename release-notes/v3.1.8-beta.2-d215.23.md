## Behavior

- The outline-house button beside the Y70 preview sets the displayed real page
  as Home. Startup shows Home; double-tapping empty background returns there.
  Widget/control contacts and drags retain their existing behavior. Missing or
  deleted Home falls back to the first real page; the temporary blank is excluded.
- Either top corner of the preview starts page reordering with one captured
  mouse/touch/pen pointer. The exact grabbed point follows the pointer through
  entry. One live preview stays above up to three blank frosted-glass neighbours
  on each side, scaled to .80/.65/.52 with responsive overlap.
- A changed valid drop saves the complete page order once, preserving page IDs,
  widgets, selected page and Home. Edge dwell reaches the full ten-page limit.
  Click, unchanged drop, Escape and interrupted gestures do not save. Failed saves
  retain the original order and show an error.
- Enter/Space picks up and drops, arrows move the destination, and Escape cancels.
  Focus, position announcements and reduced motion are supported. Same-ID profile
  switches retire stale work; failed refreshes use bounded retries and manual
  recovery while keeping the previous layout locked.

Home uses optional native/dashboard `homePageId` (`HomePageId` in native DTOs),
preserved through presets, profiles, import/export, resets and stable-ID rewriting.
An older native service discards that field, so the feature requires matching
dashboard and service source. Page reordering uses the existing ordered `pages`
contract; no new endpoint or native transport is introduced.

## Build and verification boundary

Use the component READMEs, existing .NET 10 prerequisites and pinned npm lockfile.
Build the production dashboard with `npm run build:service`. Portable Home and
reordering browser commands are documented in
[`nexus-web/e2e/fixtures/README.md`](https://github.com/Dopeman501/nexus-web/blob/fc984cf25b3c59b5a94b210045bbb08d84db8e70/e2e/fixtures/README.md).
The suites read an explicitly pinned compiled dashboard and intercept all
application HTTP, WebSocket and iframe traffic. They start no Nexus listener and
do not alter real settings or open hardware.

From `nexus-service`, the focused native command is:

```powershell
dotnet test tests/Nexus.Service.Tests/Nexus.Service.Tests.csproj -c Release -p:BuildWeb=false --filter "FullyQualifiedName~PanelHomePage"
```

The unchanged product inputs passed 1,349 dashboard owner tests across 119 files,
180 related native cases, types, scoped lint and the service-dashboard build.
Nineteen reordering and nine Home scenarios passed against both frozen and
installed dashboard files. Both mouse corners measured zero anchor drift during
entry; continuous native touch, keyboard, cancellation, failure, reload and
concurrent kiosk navigation were covered. New native Home policy coverage is
100% of its six lines and ten branches; numerical web coverage was unavailable.
Nine isolated hardware-disabled Native AOT checks passed.

The installed package verification covers 905 payload files (842 dashboard and 63
native/metadata), 376 decoded matching compressed companions, 71 served entry
assets and both retained transition-engine chunks. A normal service restart after
protected stopped-state backup preserved all seven audited configuration files,
active profile, five Y70 pages, complete layouts and exact custom-animation bytes.
The existing D215 stream returned at 1680×756/30fps with confirmed 80% brightness.
No live Home/page-order choice or exploratory hardware command was used as a test.
Physical Y70 appearance and touch remain user-operated acceptance.

The `.23` publication supplied `_NexusDevVersion=3.1.8-beta.2-d215.23` as an
MSBuild property; an ordinary source build retains the development version.
Only the service executable and existing build metadata changed among native
payload files. Repository publication does not create a binary GitHub release or
change the installed app, settings or credentials. Generated packages, test
reports, credentials, app data and protected rollback backups remain ignored.

No dependency or lockfile changed. The publication audit retains the same 29
inherited package findings (one critical and 12 high) documented in the `.22`
notes; the existing standalone Node-hosting risk remains outside this change.
