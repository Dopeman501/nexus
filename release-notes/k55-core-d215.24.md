# K55 CORE RGB lighting candidate — 15 November 2026

This implementation adds the black Corsair K55 CORE RGB (`1B1C:1BFE`) to the existing Nexus Lighting path through a dedicated headless OpenRGB controller. It represents ten physical shared RGB zones. Gray CORE and CORE TKL are separate unsupported targets.

Type Reactive uses the existing user-session keyboard helper and renderer. After choosing the physical BR, JP, UK or US keyboard layout, the editor offers zone Fade and Ripple with the same geometry in preview and live rendering. Layout is never inferred from Windows locale. The generic eligibility rule for other low-LED keyboards remains unchanged. This is independently authored zone lighting; exact iCUE Type Lighting algorithms were not recovered.

## Owners and contracts

- Headless: `nexus-rgb/openrgb-headless/Controllers/CorsairK55CoreController/` owns the independently authored packet codec, exact model/interface/descriptor checks, serialized bounded HID session, two owned buffer bindings, protected indication, keepalive and cleanup.
- Native: `nexus-service/src/Lighting/KeyReactive/K55CoreReactionLayout*.cs` owns regional physical-key geometry and card projection. The existing overlay, preview, RGB bridge and UV computation share it. Unknown layouts disable reactions until explicitly selected; ordinary RGB remains available.
- Dashboard: the existing Type Reactive editor and modal show ten shared zones and the supported effects. `useTypeReactiveConfig` and `useKeyReactiveState` retire profile/device/projection work, serialize same-owner saves and reject stale replies.
- Additive API metadata includes supported effects/layouts, `zoneLighting`, runtime profile `epoch` and CORE `layoutRevision`. Optional `expectedEpoch` and `expectedLayoutRevision` queries guard PUT/preview/press operations. Existing clients retain compatibility; clients omitting those queries do not receive their stale-request guarantees.

The headless controller reads WinLock state without changing its flag. The protected lamp is outside the ten public RGB slots. Firmware, assignments and onboard profiles are never written. Frames, keepalive and cleanup share one I/O owner; failed writes are terminal, retain pending backing bytes through handle close and are never blindly retried. Initial GET03 records the existing mode; failed partial acquisition preserves an existing software owner instead of forcing hardware mode. A bounded Windows process snapshot skips acquisition while iCUE is running or enumeration fails. This guard is not atomic against a vendor app starting afterward.
